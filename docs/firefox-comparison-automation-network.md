# Firefox → Chromium：自动化、网络与发行行为对照

日期：2026-10-29。此表从 Firefox 的实际源码修改出发，补充 Chromium 硬件/显示调查之外的范围。

## 源码身份

- 原作者修改索引：[`source-change-ledger.json`](../evidence/firefox-source-ledger.json)，原版 Firefox 151 `79eeaf756b8cee11ca4c173a7b86b04b22db707b` → 作者产品 `firefox-53` / `57a89f0152b8ada6613bf5d008db923873c955a5`，440 文件、642 hunks。下文 `S53-*` 为该索引的精确 hunk ID。
- 运行版实现逐项复核于 `firefox_stable_159` HEAD `d416cbfe5dc9884c4c3eba13ac4b94ef8fd923c2`，浏览器二进制源码为 `358357508394bb2ac288ece425ba2e7e68b94957`，维护分支 `release/159`。本表引用的是现有工作树中的实现，旧 hunk 的注释与运行实现不一致时以实现为准。
- Chromium：Linux stable `156.0.8078.73`，提交 `2f9a11097447f226133bc1a31c787291a5eeab98`。
- 该 Chromium DEPS 中的 V8：`235050a0df6db2c9d92a419af2b72fbf3b2dd73b`。源码已按固定 SHA 缓存，未用 `main` 文档代替实现。

本表的“上游已有”表示定制 Chromium 仍要对接、验证对应能力，不需要为同一功能重新做原生补丁。“运行配置”包含容器实际网络/桌面、浏览器启动配置、Python 后端及会话状态。

## 构建与首版范围

1. **沿用 Chromium 的 Linux 平台行为。**不引入 Firefox 的 Windows `oscpu`、DWrite、DirectX/ANGLE 字符串、窗口边框、Windows 字体集合等声明。Linux desktop 的插件/PDF、媒体 codec、WebGL/WebGPU、sandbox、字体和服务由最终 Chromium 构建与实际运行环境一起决定。
2. **Chromium 自动化接入工作仍然存在。**原生有 CDP input/filechooser/CSP/网络拦截，不等于 Python server 已经支持它们。首版要接 target/session、OOPIF、world/context/handle、导航/网络事件、输入与截图，而不是先复制 Firefox 的 Juggler 内部实现。
3. **首轮 native 改动仍可集中在硬件声明。**HC、CPU performance tier、内存及 Client Hints 的一致来源属于 native 数据面。网络路由、真实桌面、语言与时间初始化先由运行配置完成；humanize 属于共享 Python 动作规划与 CDP 适配。
4. **domain 与启动参数成为发行证据。**记录实际 Chromium args、profile preferences、连接方式、所有启用的 CDP domains 与浏览器 feature 集合，连同 native revision、DEPS、编译选项、容器镜像/字体/GPU/音频环境版本一起维护。
