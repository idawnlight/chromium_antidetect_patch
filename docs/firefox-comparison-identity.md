## 最明确的新增事项

现有 30 组硬件/显示清单已经覆盖 CPU、RAM、storage quota、display、pointer、外设等核心接口。与实际 Firefox 改动相比，需要补为明确开发/验收条目的有：

1. **完整区域设置链**：HTTP 语言、Navigator 语言、Intl、Date、原生表单、默认文本语言；包含未来新进程和 Worker/Worklet 首次执行。
2. **C runtime 的本地时间**：`document.lastModified` 独立于 ICU/CDP timezone；按进程固定时区能直接统一首版。
3. **真实桌面服务组合**：window manager/compositor、输入设备枚举、GTK 设置、主题/系统颜色和 app/text scale；不是只有一个 DISPLAY 环境变量。
4. **多会话运行边界**：独立 display/compositor session，避免共享桌面中互相抢 focus/occlusion；这也直接影响 rAF、计时和输入。
5. **正常 browser 功能组合**：PDF viewer、cookie/storage/partition/persistence；这些不是原始硬件 getter，但能观测极简容器/构建配置。

Chromium 专有的 `deviceMemory`、Client Hints、`cpuPerformance`、`performance.memory`、Compute Pressure、UA-CH 等继续按前一轮源码清单处理。Firefox 没有对应 hunk 不代表 Chromium 没有这项入口。

## `lastModified` 为什么必须额外列出

`.73` 的具体路径是：

```text
CDP setTimezoneOverride
  → Blink TimeZoneController
  → icu::TimeZone::adoptDefault + V8 notification

document.lastModified
  → Document::lastModified
  → base::Time::LocalExplode
  → Linux localtime_r
  → process TZ / installed zoneinfo / /etc/localtime
```

所以先让进程在 `America/New_York` 启动、ICU 与 libc 都读到同一份时区，比先启动 UTC 再只改 CDP 更直接。locale 也有类似的分层：Chromium 的 profile 语言列表、应用语言、ICU locale、GTK 区域/字体规则分别有源头。首版每身份独立进程，使用启动配置统一这些源头，再采样确认结果。

EXSLT 日期 hunk 是 Firefox 特有的已暴露功能；Chromium 只注册 common node-set 的事实表明，比较必须追到各引擎实际接口，不应照着 Firefox patch 数量补齐。
