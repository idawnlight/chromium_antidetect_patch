## 图形运行的三个真实选择

| 实际运行方式 | 网页会得到什么 | 对目标的适合程度 |
|---|---|---|
| 有正常桌面显示，并向容器提供真实 GPU render node 与匹配的 Mesa/厂商用户态驱动 | WebGL/ANGLE 与 WebGPU/Dawn 能取得实际 GPU backend；可观测到对应的 shader、limits、extension、像素和实际性能；具体加速可用性仍按这套驱动及 Chromium blocklist 判断 | **首选**。最接近普通 Linux 桌面，修改精确标识时其他执行能力仍自然保持一致 |
| X11/Xvfb/Wayland 显示存在，但没有可初始化的 GPU backend，也没有启用可用的软件 GL | screen/window/CSS 可以正常，但 WebGL context 与 WebGPU adapter 可能为 null；本机上一轮 Xvfb 观测正是这一路径 | 适合连接/显示链路开发；桌面图形基准应采用有真实可用 backend 的运行环境 |
| 显式选择软件 backend，例如 SwiftShader；或可用的 Mesa 软件实现 | 真实软件渲染能力、renderer、translated shaders、limits、性能和 WebGPU fallback 特征。保留软件 identity 与实际能力可形成一致的软件桌面环境 | 可作为无 GPU 的独立发行/测试运行方式；需单独建立基准，不能把它的字符串改成消费级 GPU 后当作硬件桌面 |

Xvfb 的职责是显示服务，它自身不提供 GPU。反过来，提供 render node 也需要同时提供可初始化的 EGL/Vulkan/驱动栈，并验证 Chromium 真正选中了该 backend。GPU compositing、Canvas raster、WebGL、WebGPU、视频 decode 是可分别启停或 fallback 的路径，应分别记录。

固定 `.73` 源码里 [ui/gl/gl_features.cc:308](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/ui/gl/gl_features.cc#308) 的 `AllowSwiftShaderFallback` 默认禁用；`IsSwiftShaderAllowedByCommandLine:276` 接受显式 SwiftShader 选择和 enable-unsafe-swiftshader。[content/browser/gpu/gpu_data_manager_impl_private.cc:489](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/gpu/gpu_data_manager_impl_private.cc#489) 只有在 `SoftwareGLAllowed()` 为真时才把 SOFTWARE_GL 加入 fallback 队列。因此不能假设“GPU 不可用就会自然得到 SwiftShader WebGL”。实际启动 flags、feature state 和实际 backend 三者要同时记录。

## 需要补进现有 inventory 的条目

1. **WEBGL_debug_shaders** translated shader source、对应 backend，以及编译/链接和图像的实际关系。
2. **WebGL GPU timer query** 与 WebGPU timestamp query 分开；扩展有无和真实 query 路径同时记录。
3. **context creation / adapter selection**：powerPreference、failIfMajorPerformanceCaveat、contextcreationerror、forceFallbackAdapter、isFallbackAdapter。
4. **独立像素交付路径**：PBO/getBufferSubData、GPU 图像转 2D/Offscreen/ImageBitmap、WebGPU buffer/texture readback、GPU→CPU canvas 策略。
5. **EME/CDM**：key system/configuration/robustness 与实际可用 CDM；与一般 codec 支持分开。
6. **环境生命周期**：音频 sink 启动/断开，media 首次/缓存/并发枚举与 devicechange，TTS 首次加载/voiceschanged/实际 utterance。

以上补充来自源码入口与 Firefox 具体 hunk 的对照。原生 Chromium 产品代码在本轮没有变更；这些是实现与容器基准的输入。
