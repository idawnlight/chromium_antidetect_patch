# Chromium 156：渲染、字体、音频、媒体的硬件关联 API

源码基线：Linux stable `156.0.8078.73`，Chromium `2f9a11097447f226133bc1a31c787291a5eeab98`。本报告来自该提交实际 C++ / IDL / DEPS，页面采样不是判定源码行为的依据。缓存位于 `source-cache/2f9a11097447f226133bc1a31c787291a5eeab98/`。外部实现按本次 DEPS：ANGLE `127e783de33425c27a70a3f48da9d9202d6a0745`、Dawn `0caf3649477f7c3ffbd4b1ca4764a81b469b1582`、Skia `a65b5cc03a5131808aec172085b7074fc66625b9`。

结论：保持真实 Linux 桌面时，可先减少直接 identity 的细节，保留真实 GPU 的执行能力和像素、真实字体渲染、正常媒体协商。WebGL 的未遮蔽 renderer/driver 字符串是一个小而明确的原生入口；WebGPU 已经默认隐藏精确 device/description，limits 也已分档；字体和音频不能只当作几个 getter，因为其主要可观察内容来自真实输出。

## 适合这条 Linux 路径的改动边界

1. 首版用同一 Linux 浏览器进程配置限制 `hardwareConcurrency` / `deviceMemory`，图形侧先记录真实能力。处理 GPU identity 时优先改 Blink 网页返回值的统一路径，保留实际 GPU 选择、ANGLE/Dawn backend、能力验证和绘图输出。
2. WebGL1、WebGL2、worker OffscreenCanvas 同时覆盖；WebGPU adapter 与 device 信息同时核对。进程配置在 renderer / worker 创建前生效，不能只在页面主 world 注入 getter。
3. 原有权限和裁减值得保留：WebGPU device / driver metadata、tiered limits、设备 HMAC 和未授权空标签、local-fonts prompt、RTC capturing gate 已经减少了一部分信息，无需先人为扩展再做屏蔽。
4. 首版需要跨机器减少渲染差异时，先统一 Linux runtime 的字体、fontconfig、音频 sink、codec 构建选项与 GPU backend。这样的变化对应实际运行环境，CSS / Canvas / DOM / Worker / playback 等多个出口会自然一起变化。
5. 像素、音频结果、GPU limits 的进一步统一属于另一组独立工程；明确分开“隐藏精确型号”和“统一输出”。本轮不移植 Firefox 伪 Windows 的字体 / ANGLE 数据或图形噪声。

## 采样与回归项目

- Window + same-origin iframe + cross-origin iframe；dedicated worker 和 OffscreenCanvas 的 WebGL1 / 2、2D、WebGPU。
- 记录 WebGL masked/unmasked 信息、extensions、典型 caps、precision，并确认 GPU identity 粗化后 readPixels / screenshot / compositor 正常。
- WebGPU 默认 / low-power / high-performance / fallback 的 info、features、limits、device.adapterInfo、简单 render / compute / map；不额外开启 developer / unsafe features。
- 字体同时测 `fonts.check`、local FontFace、DOM width / Range、2D measureText / pixels、worker OffscreenCanvas；queryLocalFonts 分无授权 / 拒绝 / 授权三组。
- 实时 AudioContext 的 sampleRate / channels / latency、显式 sampleRate、离线 DSP、Analyser 与 AudioWorklet；不将播放暂停或无声卡误判为隐藏成功。
- 未授权 / 已授权 enumerateDevices、devicechange、track settings / capabilities；MediaCapabilities 与 WebCodecs 的 SW/HW preferences、实际 codec 初始化互相对应。
- RTC capability、无采集 / 正在采集的 stats；capture、display capture、TTS 为各自的真实功能验证。
