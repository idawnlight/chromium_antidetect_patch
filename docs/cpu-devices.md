# Chromium Linux：CPU、内存、存储、网络、电池与外设源码调查

固定版本：Chromium Linux stable `156.0.8078.73`，源码 `2f9a11097447f226133bc1a31c787291a5eeab98`。V8 按此版 `DEPS` 固定为 `235050a0df6db2c9d92a419af2b72fbf3b2dd73b`。本文结论来自这些提交的实现与 IDL。运行值应由同版本原版 / 修改版对照补齐；本文本身没有把另一构建的运行结果归给 `.73`。

首版直接处理 CPU 可见值、内存声明及对应 HTTP Client Hints 就有实际价值；磁盘估计、网络质量、权限控制的外设 API 保持 Chromium 原有语义。此版本有几处与旧资料差别很大：Linux `deviceMemory` 已取 `2/4/8/16/32` 桶，`navigator.cpuPerformance` 已标为 stable，存储报告配额默认已改成 `10 GiB + usage`，而传感器内容设置默认仍是 ALLOW。

## CPU：共同 getter 与独立 tier

`NavigatorConcurrentHardware::hardwareConcurrency()` 直接读真实处理器数；`NavigatorBase::hardwareConcurrency()` 再执行 inspector override。因此只看 mixin 函数会漏掉后一个入口。`Navigator` 与 `WorkerNavigator` 都 include 同一个 mixin，WorkerNavigator 又继承 NavigatorBase。原生改动应把配置放在这个共同的网页可见路径，而不是替换全局 `base::SysInfo`，后者还参与线程池与内部资源管理。源码：[navigator_concurrent_hardware.cc:11](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/frame/navigator_concurrent_hardware.cc#11)、[navigator_base.cc:87](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/execution_context/navigator_base.cc#87)、[navigator.idl:31](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/frame/navigator.idl#31)、[worker_navigator.idl:36](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/workers/worker_navigator.idl#36)、[sys_info_posix.cc:115](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/base/system/sys_info_posix.cc#115)。

`cpuPerformance` 是另一个入口。Browser 先按核数得粗档，异步读 CPUModelName 再修订；在 Linux，源码明确指出此调用读取 `/proc/cpuinfo`。1–2 / 3–4 / 5–12 / ≥13 核的初始档为 low / mid / high / ultra，最终分类还识别 CPU 型号。Renderer 初始化时由 `RenderProcessHostImpl` 把 tier 传进去，getter 读取该值并支持 inspector override。首版配置例如 8 线程时，tier 可选择 high；不能改 HC 后仍保留 192 线程宿主计算出的 ultra。源码：[cpu_performance.cc:171](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/cpu_performance/cpu_performance.cc#171)、[cpu_performance.cc:208](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/cpu_performance/cpu_performance.cc#208)、[cpu_performance.cc:225](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/cpu_performance/cpu_performance.cc#225)、[render_process_host_impl.cc:2035](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/renderer_host/render_process_host_impl.cc#2035)、[navigator_cpu_performance.cc:15](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/frame/navigator_cpu_performance.cc#15)、[runtime_enabled_features.json5:1491](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/platform/runtime_enabled_features.json5#1491)。

CDP 已有 `Emulation.setHardwareConcurrencyOverride` 和 `Emulation.setCPUPerformanceOverride`。这是 target / inspector 级 override；源码里存在这些方法并不等于页面、新 Worker、ServiceWorker 在第一段脚本执行前都已配置。native 进程配置仍应是默认数据源；Python CDP 后端可使用已有命令做原型与对照。源码：[inspector_emulation_agent.cc:906](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/inspector/inspector_emulation_agent.cc#906)、[inspector_emulation_agent.cc:1132](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/inspector/inspector_emulation_agent.cc#1132)。

## RAM：一项声明，三条返回路径，还有堆上限

`ApproximatedDeviceMemory::Initialize` 读 `AmountOfTotalPhysicalMemory()`，就近取 2 的幂，Linux clamp 为 2–32。这个静态类在 Browser 与 Renderer 进程各有状态。修改这一共同实现可以同时覆盖 JS getter、Browser 导航请求头、Renderer 子资源请求头，前提是身份配置在相应进程初始化前到达。源码：[approximated_device_memory.cc:20](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/common/device_memory/approximated_device_memory.cc#20)、[approximated_device_memory.cc:53](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/common/device_memory/approximated_device_memory.cc#53)、[navigator_device_memory.cc:14](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/frame/navigator_device_memory.cc#14)、[client_hints.cc:240](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/client_hints/client_hints.cc#240)、[frame_fetch_context.cc:671](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/loader/frame_fetch_context.cc#671)。

`performance.memory` 的 used / total 是软件分配状态，`jsHeapSizeLimit` 则是 V8 上限。普通 site isolation 锁定的 Renderer 用 precise 模式，只有 50 ms 的查询缓存；并非总会返回旧资料说的粗桶。非 site-locked 情况才使用 100 桶并缓存 20 分钟。源码：[window_performance.cc:352](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/window_performance.cc#352)、[memory_info.cc:47](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/memory_info.cc#47)、[memory_info.cc:79](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/memory_info.cc#79)、[memory_info.cc:115](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/memory_info.cc#115)。

`gin::IsolateHolder::getDefaultIsolateParams` 把真实物理 / 虚拟内存交给 V8 `ResourceConstraints::ConfigureDefaults`，V8 按 RAM 选代际空间。固定 DEPS 的这版 V8 在 Linux 64-bit 默认 old generation 上限达到 4 GiB 所需的内存是 8 GiB；大内存宿主与 8 GiB profile 常落在同一上限。选择较小的 profile 需把真实 heap limit 放入对照表再决定是否增加有针对性的约束；动态 used / total 不应硬写成常数。源码：[isolate_holder.cc:192](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/gin/isolate_holder.cc#192)、[api.cc:589](https://chromium.googlesource.com/v8/v8/+/235050a0df6db2c9d92a419af2b72fbf3b2dd73b/src/api/api.cc#589)、[heap.cc:357](https://chromium.googlesource.com/v8/v8/+/235050a0df6db2c9d92a419af2b72fbf3b2dd73b/src/heap/heap.cc#357)。

`measureUserAgentSpecificMemory` 默认要求 cross-origin isolation，Window 返回该页面及其 dedicated workers 的归属内存，Shared / Service Worker 可各自调用；DedicatedWorker 没有该方法。结果包含 JS / DOM / Canvas / shared 实际分配，随机的是 breakdown 顺序。源码：[performance.idl:68](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/performance.idl#68)、[measure_memory_controller.cc:100](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/measure_memory/measure_memory_controller.cc#100)、[measure_memory_controller.cc:288](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/timing/measure_memory/measure_memory_controller.cc#288)。

## CPU pressure 与执行能力

`PressureObserver` 在 Linux runtime stable，对 Window、DedicatedWorker、SharedWorker 开放，要求 secure context 和 `compute-pressure` 策略；没有设备 chooser。Browser 会判断 active / focused 等条件。Linux probe 从 `/proc/stat` 读取所有核的两次计数差，计算平均利用率；网页收到四档 state，不会收到裸 utilization 或 CPU 型号。

Browser converter 在基准阈值 `.6/.75/.9/1` 与另一组 `.5/.8/.85/1` 间按 120–240 秒随机间隔切换，且有迟滞；Renderer 另有 sample interval 与过快变动的延迟机制。这是已经粗化的动态硬件状态。首版应先实测是否需要身份级配置该功能；仅改 hardwareConcurrency 不会改变 pressure 的底层负载计算。源码：[pressure_observer.idl:12](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/modules/compute_pressure/pressure_observer.idl#12)、[pressure_observer.cc:65](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/modules/compute_pressure/pressure_observer.cc#65)、[pressure_service_for_frame.cc:34](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/compute_pressure/pressure_service_for_frame.cc#34)、[cpu_probe_linux.cc:64](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/components/system_cpu/cpu_probe_linux.cc#64)、[cpu_pressure_converter.cc:21](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/services/device/public/cpp/compute_pressure/cpu_pressure_converter.cc#21)、[pressure_observer.cc:150](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/modules/compute_pressure/pressure_observer.cc#150)。

Wasm 这版 feature 集合由 `WasmEnabledFeatures::FromFlags`、`FromContext` 构建，代码列出的来源是 V8 feature flags、jitless 和 context callbacks；没有从此代码得出“网页可直接 enumerate 宿主 AVX/SSE”这样的结论。并行 Worker 吞吐、Wasm 执行时间与实际分配成功与否，属于运行计算结果。源码：[wasm-features.cc:17](https://chromium.googlesource.com/v8/v8/+/235050a0df6db2c9d92a419af2b72fbf3b2dd73b/src/wasm/wasm-features.cc#17)。

## 磁盘：报告配额与实际分配不同

`QuotaManagerHost::QueryStorageUsageAndQuota` 已经调用 `GetUsageAndReportedQuotaWithBreakdown`，不直接回传内部可分配配额。`kStaticStorageQuota` 和 `kIncognitoStaticStorageQuota` 在这版均默认 enabled。一般返回 `usage + 10 GiB`；普通模式总磁盘 <10 GiB 时返回 `usage + ceil(total GiB)`；隐身强制最大静态值。未显式指定 quota 的 bucket 路径也调用同一 CalculateReportedQuota；指定 quota 的 bucket 报告请求值，unlimited storage 走内部值。真实数据写入仍按磁盘剩余量与内部 quota 管理。源码：[quota_manager_host.cc:26](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/content/browser/quota/quota_manager_host.cc#26)、[quota_features.cc:37](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_features.cc#37)、[quota_manager_impl.cc:138](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_manager_impl.cc#138)、[quota_manager_impl.cc:1177](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_manager_impl.cc#1177)、[quota_manager_impl.cc:1274](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_manager_impl.cc#1274)。

内部普通临时 pool 仍是磁盘总量的 80%，单 StorageKey 配额是 pool 的 75%，即常见旧说明里的约 60%；incognito 的内部 pool 仍按 RAM 15–20% 选择。这些内部数值不能直接当成 `.estimate().quota` 的当前网页可见值。源码：[quota_settings.cc:35](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_settings.cc#35)、[quota_settings.cc:120](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_settings.cc#120)、[quota_features.cc:26](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/storage/browser/quota/quota_features.cc#26)。

## 网络：保留真实连接与现有量化

`navigator.connection` 的 RTT/downlink 并非网卡型号或标称带宽，而是 NQE 实际网络质量估计。`NetworkInformation` 在无监听时查询 notifier，有监听时缓存上次通知，并发 change 事件。`RoundRtt` / `RoundMbps` 使用 hostname 与进程 salt 产生 0.90–1.10 multiplier，再限制上限与步长；同一处理也被 Renderer Client Hints 复用。Linux stable 默认没有 `type/downlinkMax`，因为 `NetInfoDownlinkMax` 的 default status 是 experimental。首版保留这些值能让网络页面适应真实连接；若后续配置则必须同时覆盖事件值与 client hint。源码：[network_information.cc:134](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/modules/netinfo/network_information.cc#134)、[network_information.cc:176](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/modules/netinfo/network_information.cc#176)、[network_state_notifier.cc:370](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/platform/network/network_state_notifier.cc#370)、[network_state_notifier.cc:385](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/platform/network/network_state_notifier.cc#385)、[frame_fetch_context.cc:689](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/core/loader/frame_fetch_context.cc#689)、[runtime_enabled_features.json5:4384](https://chromium.googlesource.com/chromium/src/+/2f9a11097447f226133bc1a31c787291a5eeab98/third_party/blink/renderer/platform/runtime_enabled_features.json5#4384)。

## 电池、传感器、外设：按真正开放条件决定

## 首版建议与验证矩阵

第一组 native patch 聚焦：共享网页可见的 CPU 核数、Browser CPU tier、公共 DeviceMemory 与全部 Client Hints 数据源。配置应在 Browser / Renderer / Worker 执行网页脚本之前生效。采用一身份一 browser process，避免把 process-global 静态内存桶混用为 context 级设置。默认核数 / 内存组合可选常见 Linux 桌面档，例如 8 线程、8 GiB、high tier，实际值由维护层明确写入 profile。

电池作为可选桌面 profile 字段；Storage / NetInfo 沿用上游；外设接口保留权限及硬件缺失语义。`performance.memory` 先记录 heap limit 与占用，不对动态内存使用量造常数。

验收按“数据源一致性”逐项跑：

1. 顶层 Window、同源 iframe、跨进程 iframe、DedicatedWorker、嵌套 Worker、SharedWorker、ServiceWorker、重启后的 ServiceWorker 读取 HC / DeviceMemory，重复读取、导航重用进程、崩溃重建后仍按同身份。
2. 带 Accept-CH 的本地 HTTPS 测试端点分别记录导航与子资源的 DeviceMemory 头，与页面及 Worker 的 JS 值对照；覆盖新旧头名。Worker 请求头是否发送依对应路径的支持状态实测，不以 getter 相等代替请求结果。
3. Window CPU tier 与 HC 按配置组合；创建时间最早的脚本读取也一致。
4. 记录 site-locked Renderer 的 heap limit、used/total、隔离页面的 memory measurement，与配置内存档对应关系。
5. 普通 / 隐身下 StorageManager 与 StorageBucket quota / usage，确认上游默认静态报告仍在。
6. NetInfo 直接 getter / change 事件 / Request Hints 对照；Battery 初始状态与事件一致。
7. 无授权新 profile 的 USB/HID/Serial 列表与真实普通版一致；有授权时继续按许可返回。记录 sensor 硬件缺失与手柄交互后的变化，避免全局删除 API。
